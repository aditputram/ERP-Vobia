Urutan penggunaan & acceptance test

Ikuti dari atas ke bawah. Jangan melompat ke Sales commit sebelum Master Product dan FIFO Opening untuk SKU uji siap.

Local UAT

SEBELUM MULAI

Data uji yang perlu disiapkan

  • Export canonical Bank Data dalam .xlsx/.csv.
  • Pilih 1–3 SKU uji dengan Opening Qty dan Frozen COGS per 1 Agustus 2026.
  • Siapkan satu supplier dan satu warehouse nyata.
  • Siapkan file Sales mentah Shopee/TikTok dan file Traffic mentah. Gunakan salinan export; jangan ubah workbook live.
01

Master Product

Buka Data Import → upload Bank Data → periksa warning/blocker → Approve. Expected: SKU dan mapping marketplace muncul; file identik ditolak.

02

Warehouse & FIFO Opening

Buka QC · Inbound · FIFO → tambah warehouse → post Opening SKU uji memakai Frozen Unit COGS. Expected: movement Opening dan FIFO layer terbentuk; opening negatif menjadi exception.

03

Sales marketplace

Buka Sales. Tabel paling atas memberi periode export yang dibutuhkan. Upload file → review new/status/retur/blocker → Approve. Expected: transaksi canonical, Sales Out, FIFO allocation, dan status nonfinal tetap meminta re-import.

04

Sales manual

Di Sales, isi Source aktual, invoice, SKU, qty, harga net, dan status. Expected: snapshot Gross/Net/COGS/GPM tersimpan; harga net di atas retail membuat Gross = Net, bukan discount negatif.

05

Traffic

Buka Traffic → pilih source dan satu periode bulan → upload → review mapping product → Approve. Expected: duplicate product/variation diblokir. Bulan lalu boleh Mark complete; koreksi berikutnya wajib Re-open dengan alasan.

06

Projection

Buat Scenario. Pilih Target Month, Scope (Status/Category/Product), metode, parameter → Preview → Apply. Expected: Product mengalahkan Category, Category mengalahkan Status. Approve final qty per SKU dalam bilangan bulat.

07

Incoming Plan → PPIC

Pada projection Approved, masukkan prior ending dan optional target Stock Ratio → Create Incoming → Approve. Expected: final tidak boleh di bawah minimum dan PPIC Requirement terbentuk otomatis.

08

Review & Release PO

Buka PPIC & Purchase Order → tambah supplier → pilih requirement + qty → Create Draft → buka Draft → Release. Expected: nomor PO-VOB-MM/YY-NNN muncul dan COGS dibekukan.

09

QC

Catat inspected, passed, failed, dan disposition bila failed. Expected: cumulative inspected tidak bisa melebihi PO Qty; QC belum menambah stock.

10

Inbound

Catat actual receipt dengan GRN/reference unik. Expected: received tidak bisa melebihi QC Passed; movement Incoming dan FIFO layer memakai COGS PO.

11

Return fisik

Status marketplace Retur hanya membuat Expected Return. Catat penerimaan fisik dan condition. Expected: hanya Sellable menambah stock serta memulihkan FIFO layer transaksi asal.

12

PO Aging & correction

Refresh close/reopen. Expected: PO close hanya saat outstanding inbound dan layer PO sama-sama nol; sellable return dapat membuka kembali. Adjustment wajib evidence, reason, tanggal, dan cost.

13

Reconciliation

Run reconciliation. Expected: record-level Sales/Movement, QC/Inbound, FIFO, balance, dan PO close lulus. Inventory exception tetap terlihat terpisah dan tidak dipaksa menjadi OK.

CUTOVER GATE

Belum boleh menghentikan Google Sheets

Setelah satu siklus UAT lulus, jalankan parallel run minimal tujuh hari berturut-turut. Cutover baru boleh disetujui bila tidak ada duplicate, missing movement, unexplained stock difference, atau critical reconciliation issue.
